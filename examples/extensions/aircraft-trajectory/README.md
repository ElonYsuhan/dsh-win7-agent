# 飞机轨迹计算 MCP 连接配置

本包连接已有 `http://127.0.0.1:4331/mcp`（Streamable HTTP）服务，不包含服务端、计算算法、运行环境或下载器。需要先启动原有 nexa-kinetix 服务。

在 Agent 能力中心导入 `.mcp.pgk`，安装后启用。Agent 在连接时通过 `tools/list` 读取最新的工具描述和完整输入 Schema，注册进现有 Cordis 工具系统。模型产生调用后由 Agent 后端执行 `tools/call`，结果或错误随工具消息返回模型；不在浏览器里直接调用 MCP。只读计算权限不提升 Agent 的运行权限。

## 示例

对 Agent 说：

> 使用飞机轨迹计算工具：ENU 航点 (0,0,1000) 到 (1000,0,1000)，速度100米/秒，转弯率10度/秒，采样间隔1秒，最大爬升率20米/秒，返回总距离、时间和首尾采样点。

原始参数见 `example-input.json`。此例返回1000米、10秒、11个采样点。

航点是局部 ENU 米制坐标，不是经纬度；速度为水平速度。工具是定速和圆弧转弯轻量模型，不包含动力学、地形、碰撞或真实飞行验证。

## 主机位置

`127.0.0.1` 指 Agent 后端所在主机。仅当后端与轨迹服务在同一台机器时使用本包原地址。浏览器、远程服务器、虚拟机和容器有各自的 localhost；跨机器时应将 manifest 的 URL 改成轨迹服务对 Agent 后端可达的地址，再重新打包，不要把前端机器的 localhost 当作后端地址。

如改用 Agent 设置中的手工 MCP 配置，使用 transport `http`、permission `read` 和相同 URL 即可；与本包二选一，避免重复注册。手工服务建议 ID 为 `aircraft-trajectory`。包级工具名由现有安装器生成独立命名空间，请以能力中心实际发现的工具为准。

错误不会被冒充成功：参数错误由远端校验并以错误工具结果返回；服务离线会显示连接失败；取消和超时沿现有 MCP 客户端处理。其他机器安装后仍需要其后端能访问该服务。
