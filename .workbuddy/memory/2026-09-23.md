### 沙箱坑（这次花时间最多）
1. **沙箱禁止写入任何 `.asar` 路径**。表现：`createBrokerPolicyError: Invalid package .../resources/default_app.asar`（栈在 `node-brokered-fs-shim.cjs` 的 `wrappedCopyFileSync`）。验证方式：同目录 `cp probe.txt other.asar` → `Brokered file token refused: modify backup failed`；`cp probe.txt probe.txt` 正常 → **是扩展名 `.asar` 被拦，不是目录或权限**。
2. **沙箱对「复制源」另有策略闸**：`Brokered host copy source refused by file policy: prompt`，具体点是 `src/main/agent/md-skills/03-official-plugins/cb_teams_marketplace/document-skills/pdf/reference.md`（`file-read-data`）。这文件本身随便读（`Read`/`wc` 都行），只有被 `fs.copyFileSync` 当源时才会触发。
3. **结论**：`build-desktop.js all` 必须在**放开沙箱**（escalation approved）下跑；只在 Bash 工具里加 `dangerouslyDisableSandbox: true` 时**必须前台调用**——同样的参数丢进后台任务不生效，照样报沙箱拦截。
4. `NODE_OPTIONS` 里挂着 `--require=.../node-language-shim.cjs`（WorkBuddy CLI 的 shim），上面的拦截都来自它这一层，跟 shell 沙箱是两件事。

### zsh 两个静默坑（又栽一次，务必记住）
- **glob 无匹配直接报错并中断整条命令**：`rm -rf release/desktop/.stale-*` 在没有残骸时 `(eval):1: no matches found`，`&&` 后半段全不执行（表现为「build=1 但日志文件都不存在」）。解法：命令前加 `setopt +o nomatch;`。
- **zsh 不对无引号变量做分词**：`FILES="a b c"; for f in $FILES` 只跑一轮，`$f` 是整串。解法：`for f in ${=FILES}`。

## R28 · 用户报的两个 bug（都复现了，都修了）

### ① 思考过程「还是会丢失」→ 真因：`saveThinkingProcess` 逐轮**覆盖**而不是累积
- 机理：`beginThinking` 只在 `state.currentThinking` 为空时新起块；一轮结束后 `endThinking` 把它置空，**下一轮就会另起一块**。而旧实现写回是 `session.processHtml = content.innerHTML`（只写本轮那一块）→ 会话里第二轮一开始，第一轮记下的过程被整段抹掉。**DOM 里当下还能看到两块，一重载/切走再切回就只剩最后一轮** —— 这就是「有时（换个时机看）就丢了」的来源。
- 修法（`src/renderer/app.js`）：新增 `state.thinkingBase`（本轮块**之外**、这条会话已记下的过程）+ `mergeProcessHtml(base, fresh)`，写回时 = base + 分隔 + 本轮。谁新起一块谁负责设 base：`beginThinking`（另起）= 此前的 `processHtml`；`resumeThinking`（续接，已有内容就在块里）= **空串**，否则保存回去会自己叠自己。
- 同轮多次写回仍按元素级追加（不变）；后台会话那条 `commitProcessRecord` 路径本来就把 seed 放在块里，语义一致，只需过一遍 `mergeProcessHtml` 做裁剪。
- **必须配上限**：累积后 `processHtml` 会长，加了 `MAX_PROCESS_HTML = 262144`（按 `THINKING_TURN_SEP` **整轮**从头丢，绝不切半句——切中间会把 HTML 标签切成两半）。这条上限是 R28 引入的，别删。
- 轮间分隔 `THINKING_TURN_SEP = '<div class="thinking-turn-sep"></div>'`，CSS 在 style.css（虚线，用 `var(--border)`）。

### ② 模型切换后界面「没切换成功」→ 真因：`selectProviderModel` 的早返回分支漏渲染

### 收尾清理 + 一条用例稳定性教训
- **`close()` 是先 SIGTERM、3s 后才 SIGKILL**。E2E 里「进程消失」那条一开始写「固定 sleep 900ms 再探测」→ 偶发假红（实测 `waited=3200ms` 才死，因为走的是强杀兜底）。改成**轮询**（200ms × 30）后连跑两次都稳。**凡是等进程/服务状态变化的断言都别用固定 sleep。**
- `reapBrowsers()` 里补了 `fs.rmSync(userDataDir)`：exit 处理器里为同步操作，正好合适（`close()` 的清理是 setTimeout 起的，强杀路径跑不到）。
- **清掉 8080 上的残留实例**（PID 88474）：cwd 在 `/private/var/folders/.../T/dsh-browser-test-*`、跑的 Electron 二进制在 `~/.Trash/Agent-mac-arm64 .../Agent.app`（早被清掉的那个包）—— 彻底的 smoke 残留。危险点：它 health 报同一个 app id，**用户自己的实例会把它当「自家实例」复用**，于是界面读的是它的空设置和临时工作区。kill 后 8080 已释放。顺手清掉 14 个同前缀临时 profile 目录（现在三者均为 0）。
- 最终包内对账：5 个改动文件在 win-x64 / linux-arm64 / mac-arm64 三个包里哈希与源码全一致（`browser-driver.js` 因补 rmSync 变成 `b866acaa088f`）。
