# 2026-10-20 工作流人工节点：交互类型 + 真实驳回 + 画布工具收敛

## 做了什么

- **交互类型契约**（新）`src/main/contracts/workflow-interaction.js`：`{version:1,type:'handle'|'review'|'approve',returnTo:'previous-human'|节点id}`。
  `modes()` 把类型翻译成旧的 humanModes（approve→approval / review→read / handle→review，另加 upload），
  旧定义没有 `interaction` 时行为完全不变。
- **真实驳回**（替代“驳回=暂停”）：`submit` 收到 `decision:'reject'` 时校验退回目标（默认最近的上游人工办理节点，
  可在高级设置指定），写 `node-returned` 事实 → 目标及其下游**全部重置为 pending**，attempts/timeline/产物文件保留
  （产物文件名带 attempt 后缀，旧版本不被覆盖）。原因写进 timeline，`returnedFrom` 给界面出横幅。
- **外部副作用核查点**：退回后若会重放已执行过的 rest/agent/tool 节点，执行器先停在 `external-checkpoint`
  （status=paused，error 文案含“核查…确认…外部”），必须 `resume({confirmExternal:true})` 才真重放。
- **编辑面板**：默认只显示 名称 / 处理描述 / 交互类型；附件、填写项、补充意见收进折叠的「补充内容」（附件默认关闭）；
  旧的四种处理方式收进「兼容配置」。处理描述高度压到 88px，保证交互类型在 1366×768 首屏可见。
- **执行面板**：审批节点给 通过/驳回 单选 + 驳回原因（默认隐藏、选驳回才出现且必填）；办理/审阅一键完成，
  不再勾选“我已审阅”、不再强制结论；`review` 提交即写 reviewed=true。驳回用警示色横幅，不显示成技术失败。
- **画布**：只留 选择/移动、连线、框选；空白拖动平移、滚轮围绕指针缩放、框选后拖任一卡片整体移动
  （`workflow-canvas.js` 里改写 `processNodeSelected`，否则点选会把多选收缩成一个）；去掉手形/放大/缩小/适应全部，
  “恢复100%”进右键菜单（`canvas.processMenu` → `workflow-canvas-menu`），底部保留缩放比例。
- **新增验收**：`scripts/workflow-interaction-smoke.js`（服务/状态机，已进默认 check 链）、
  `scripts/workflow-interaction-e2e-smoke.js`（真实窗口：编辑器三字段、一键办理、驳回退回、重跑完成）。

## 踩到的坑

- `node-waiting` 里 `step.waitKind` 对普通人工节点是 `'human'`（不是 undefined），当 truthy 用会误判——
  要判 `['agent','evaluation'].includes(step.waitKind)`。
- 执行面板的提交按钮**不在** `.workflow-current-task` 里，是 `.workflow-task-actions`（right 容器的直接子元素）。
- `<details>` 折叠 + 子元素 display:flex 时 Chromium 仍会画出来，必须显式
  `details:not([open]) > *:not(summary){display:none!important}`；`[hidden]` 也压不住带 display 的类，得单独写规则。
- `workflows-e2e-smoke.js` 的 `driver.launch` **必须传 `noSandbox`**，否则窗口起来就 CDP_DISCONNECTED；
  这个问题在 HEAD 上一样，属于脚本缺陷不是环境问题。它还会因为“新人工节点默认 办理”而走到新表单，
  已在该脚本里 `delete n.properties.interaction` 固定测试旧布局。
- `:has()` 在 Chromium 108 可用；但 `grep "a\|b"` 在这台机器上继续骗人（BSD grep），已全部改用 Grep 工具。

## 补记（同一轮继续优化）：多选拖动 + 折叠聚焦

- 多选拖动其实由 LiteGraph 原生完成（`processMouseMove` 里遍历 `selected_nodes` 等距位移），
  我们只需要 `processNodeSelected` 覆写在“已选中且多选、无 Shift/Ctrl/⌘”时提前返回。
- **测试脚本踩的两个坑**：① 两次 CDP 按下间隔 <300ms 会被当成双击，走 `onShowNodePanel`
  把选择塌缩成一个并 `bringToFront` 重排 `graph._nodes`（所以断言要按 node id 而不是下标）；
  ② `last_mouse` 只在 `processMouseMove` 里更新，合成拖拽必须先发一次 hover move 再按下。
- **折叠区里的 focus() 静默失效**：`#workflowNodeAdvanced` 等 details 关闭时子元素 `display:none`，
  对内部输入框 focus 什么都不会发生（activeElement 停在 body）。`renderStructured` 的 `redraw`
  现在先逐个打开祖先 details 再聚焦。
- 一次手工补丁把 `processingForEditor` 的闭合 `}` 吃掉（多出来的 `}` 挂在下一个函数行尾），
  语法仍合法但 `renderHumanExtras` 变成嵌套函数、后续函数掉出 IIFE 作用域，表现为
  `revealInPanel is not defined`。教训：改完压缩风格的单行函数用 `node --check` + 括号平衡扫描确认。
- `package.json` 补 `check:workflows:browser` → `scripts/workflows-e2e-smoke.js`（之前没有入口）。
