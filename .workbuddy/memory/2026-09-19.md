## 11:54 修复"每条回复下面都显示复制和删除"
- 用户反馈：所有回复消息下方都出现复制+删除按钮。
- 根因：`src/renderer/app.js` 的 `attachBubbleActions(wrapper, role, body)` 里，用户分支写 `if (role === 'user') { return row }`，**else 分支无条件给"非用户"气泡挂复制+trash**。于是 `tool` / `tool-result` / `notice` / `error` 四类气泡也各带一份操作行，看起来就是"每条消息都有按钮"。
- 修法：
  1. 函数开头加守卫 `if (role !== 'user' && role !== 'assistant') return null`，只保留用户消息与助手回复带操作。
  2. 把"最后一条消息操作行保持常显"的逻辑（清除上一个 `.actions-visible`、给当前 row 加类）挪到 `if (role === 'user') return row` **之前**，否则用户消息无法承接常显状态。
- 测试盲区一并补掉（这是该 bug 之前测不出来的原因）：
  - `scripts/renderer-smoke.js` 的 DOM shim 里 `classList` 与 `className` 各存一份状态（`classList.add` 不反映到 `className`，CSS 选择器匹配读到的是空的）→ 改为共用同一份 `el.className`（add/remove/contains/toggle 后回写）。
  - shim 的 `querySelectorAll` 恒返回 `[]` → 补 `parseCompoundSelector` / `matchesCompoundSelector` / `querySelectorAllShim`，支持 `.a.b` 复合选择器。
  - 新增 4 条回归断言：4 条消息 → 恰好 4 个操作行；只有最新一条常显（visible=1）；用户消息操作行在 `.bubble-group` 内、助手消息操作行仍在气泡内；**tool/tool-result/notice/error 气泡不带任何操作按钮**；最后一条是用户消息时也承接常显。
  - 反向验证：临时把守卫去掉重跑 → 136/138 FAIL（噪声气泡上多出 5 个操作行），确认测试真能拦住回归，随后恢复。

## 12:22 「双击新版自动接管旧版」更新机制
- **需求澄清**：我先给了「内网更新源 + 检查更新 + 下载」的方案，用户直接否掉：「下载个毛线，我意思下次直接点击安装新的程序，需要把本地的原来的处理掉，直接更新，你看咋合适」。
  真实诉求 = **把新包解压出来双击，程序自己把旧的那份替换掉并重启**，不要任何下载动作。
- **方案（纯 JS，不加工具链）**：`<userData>/install.json` 记录「当前生效的是哪一份程序」`{path, version, pid}`。
  它与程序目录无关，所以包解压到哪都读同一份登记。启动时若登记里的 path ≠ 当前 path → 判定为「双击了另一份」→ 显示替换确认页。
  确认后：关旧实例（整个进程树）→ 旧目录改名（**改名同时就是文件锁探测**，Windows 上目录里有占用文件时改名必失败）→ 复制新版到原名位置 → 删改名后的残留（删不掉留给下次 `cleanupTrash`）→ 从旧位置重启 → 自己退出。
- **改动清单**：
  - `shell/installer.js`（新，纯 Node 可单测）：manifest 读写 / `packageDirOf` / `mainBinaryOf`(读 Info.plist) / `samePath` / `compareVersion` / `isAlive` / `killTree`(win 走 taskkill /T /F) / `waitGone` / `copyTree`(重建符号链接+保权限) / `cleanupTrash` / `replacePackage` / `relaunch`

  - `shell/main.js`：`resolveUpdate()` 排在**单实例锁之前**（否则旧版握着锁，新版直接退出，永远看不到提示）；`runUpdate()` / `useCurrent()` / `relaunchArgs()`；`--dsh-auto-update` 静默更新；设置页显示版本与程序路径

## 14:00 双击顶栏不缩放（用户报障）→ 自己接回 macOS 原生手势
- 用户问：**「为啥双击上边栏目不能最大化到当前窗口，mac 其他应用都可以的」**。原因说白了：**那条原生标题栏是我们自己藏掉的**（`titleBarStyle:'hidden'`），AppKit 那套「双击标题栏缩放」的手势是标题栏带的，跟着一起没了；`-webkit-app-region: drag` **只负责拖，不含双击**。

- **两个判断都先用探针实测，没靠猜**：
  - 探针 1：`titleBarStyle:'hidden'` + 拖拽带，双击后 `isMaximized()` 仍是 `false` → **原生确实不代劳**；顺带确认 `systemPreferences.getUserDefault('AppleActionOnDoubleClick','string')` 在 Electron 22 上**能读到**（本机返回 `"Maximize"`，`defaults read` 查过该键没设过，就是 macOS 默认值）。
  - 探针 2（A/B）：在拖拽带里挂 `dblclick` 计数 —— **计数会动**，说明**拖拽区照样收得到 DOM 事件**（这条决定了实现可行）；同时发现 `sendInputEvent` **走不到系统拖拽那条路**（窗口坐标不变），所以它测不出原生行为，只有真实鼠标事件才算数。
- **实现**（`shell/main.js` + `shell/preload.js`，`src/main/main.js` + `src/main/preload.js` 各一份同款）：
  - preload：`document` 上**事件委托** `dblclick`（主窗口的 DOM 是页面脚本建的，直接绑元素会绑空）→ 命中 `#titlebarDrag, .brand` 才回发 IPC，再**排除** `button, a, input, select, textarea`（拖拽区里按钮自带 `no-drag`，双击它们不该顺手缩放窗口）；**只在 `process.platform === 'darwin'` 接**（Win7/Linux 原生标题栏还在，不能抢）。
  - 主进程：`ipcMain.on('shell:titlebar-dblclick')` → `titlebarDoubleClickAction()`（读 `AppleActionOnDoubleClick`：`Maximize`/`Minimize`/`None`，取不到退回 `Maximize` 不抛）→ `applyTitlebarDoubleClick(win, action)`（maximize↔unmaximize 切换 / minimize）。
  - 两个函数**故意拆成可注入的纯函数**（`process`、`systemPreferences` 走参数），就是为了让守卫能**抠出来真跑**而不是 grep。
- **守卫**：
  - `shell-chrome-smoke.js` **53 → 97 项**。新增 `loadFunction(source, name, envNames)`（数括号配对抠函数 + 注入依赖），对**两个入口**各跑一遍：5 个偏好值（含未设置/异常值）、取不到偏好不抛、`win32` 不接管、假窗口上 maximize/unmaximize/minimize/none/已销毁 五种分支；外加**两份拷贝逐字一致**的漂移检查；两个 preload 各 5 条（接了双击 / 只在 darwin / 回发通道 / 只认拖拽区 / 排除按钮）。

- 根因：R20 给 `handleEvent` 加了 `if (not(isCurrent)) return`（非当前会话事件整体丢弃）——**目的对（A 的增量不能画到 B 上），但顺手把「过程记录」也一起丢了**。一条会话整轮都在后台跑完（用户在别的会话里干活）时，它的 `assistant:thinking` / `tool:start` / `tool:result` 从没进过 `saveThinkingProcess` → `session.processHtml` 一直是空串 → 切回去整块「思考过程」不存在。只有被用户盯着跑的那条留下过程，正好对上「有的会话没了」。

## Round 23（用户问「已经支持并发了，这条提示是不是多余」）—— 提示条语义收窄
- 用户带截图（`#composerRunHint`「另一条会话正在执行，当前会话可以同时发送」）问：既然已经支持并发，这条是不是多余了。**判断是对的** —— 它是 R19 单实例时代的产物（那时「别的会话在跑」= 真的发不出去），R20 换 AgentPool 后这个前提没了，留下的是纯噪音：橙色点在深色界面上很容易被读成报错，而它说的其实是「你可以正常发」。
