## 通用工作流引擎方案（设计，未动代码）

用户澄清了真实需求：**不是**把能力中心（Skill/MCP/插件/定时任务）接到工作流节点上，
而是「给一份**软件的场景文件**，按软件使用流程生成一条流程」+ 更一般的
「任务拆解 → 需求分析 → 出报告」这类**通用工作流**。要一份方案。

### 读现状得到的硬事实（`src/main/runtime/plugins/workflow-nodes.js` + `docs/WORKFLOWS.md`）
- 只有 4 类节点：`input` / `template` / `ai` / `output`；`ai` 节点里写死 `tools: []` 并显式拒绝 tool_calls。
- `flow/workflow-policy.js` 是**纯 DAG**：拓扑排序 + 逐个执行，**无条件分支、无循环、无节点级并行**。
- 端口只有 `slot` 0/1 且只走**文本**；节点参数只有 `node.text`（16000 字上限）。
- 只有 `output` 存文本，**没有断言/评估**；限额：20 个 AI 节点、单节点 128KB、累计 1MB、10 分钟。
- 已有扩展点 `workflowNodes.register(definition, execute)`，`execute({node,input,signal,settings})→文本`。

### 给用户的两个结论
1. **「拆解→分析→报告」现在就能跑**（3 个 ai 节点串起来即可）。
   **「在地图→在装备→配置行为→推演→结束评估」跑不了**，卡的是控制流、结构化数据、评估——
   不是模型能力问题。
2. **能力一半该由 Skill 提供**：领域知识/步骤口径 → Skill；副作用 → 受控工具；
   **控制流必须引擎原生**（分支/循环/汇合/超时），否则流程退化成不可复现的长 prompt。

### 方案落在 `docs/WORKFLOW-V2-PLAN.md`
五层模型（触发 / **编排** / 步骤 / 能力 / **产物与评估**，首版缺中间两层的控制流与评估）；
分四阶段：
- **P0** 控制流 + 结构化数据：契约升 v2（v1 不受影响）、`condition`/`merge`/`iterate`/`assert` 四类新节点、
  具名端口、节点输出可为对象、模板支持路径引用；`workflow-policy` 从拓扑排序改成小型解释器。
- **P1** 能力进流程：`skill` 节点（读 Skill 正文当系统提示）、`tool` 节点（显式幂等/权限/超时，
  **不可重放副作用不自动重放**）、`ai` 节点可选受控工具模式（复用 `tasks.js` 的 `runUnattended` 限额）。
- **P2** 场景 → 流程：产物是**草稿**进画布供人审阅，不直接落库执行；复用现成 Agent 能力产出合法 JSON。
- **P3** 触发与产物闭环：定时任务执行工作流、`task` 节点反向触发、markdown 报告、`human` 人工介入。
建议先只做 P0——没有控制流，接 Skill 也只是把复杂度塞进提示词。
