# 设计走查清单

根据流程风险选择适用情景，记录起始输入、操作人决定、预期下一待办、退回范围、产物及外部操作次数：

1. 一次通过：每步只承担一个动作，所有输入均有来源，结束能交付。
2. 资料不足：审核退回正确的补正人；原有内容与驳回依据可见。
3. 审批驳回：修改后需要重做的审核确实在影响范围内；没有跳过必需审批。
4. 再次驳回：旧任务ID失效、尝试历史保留；不会生成重复流程定义或无限循环。
5. 中途故障：异常状态可定位；恢复上下文不自动重放结果不确定的外部操作。
6. 重复提交：重复点击不能重复审批、重复付款或把不同业务实例混在一起。
7. 外部已成功但响应丢失：先核查真实结果/幂等键，再决定是否重试；Skill 不提供 exactly-once 保证。
8. 能力缺口：条件分支、角色分派、会签、定时升级或补偿如果尚不支持，明确列出，不能在草稿说明里宣布已实现。

结构校验与业务正确性分别报告。保存成功只说明草稿通过本地结构检查；设计走查不能冒充模型质量评测或真实业务验收。用户只要求设计时，不为验证而自行运行业务。
