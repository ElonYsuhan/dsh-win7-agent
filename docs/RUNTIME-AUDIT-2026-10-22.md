## 架构与协议结论

- Cordis 仍是唯一装配与生命周期底座。契约、纯策略、纯 reducer、执行/仓储四层保持分离。
  架构守卫现在检查所有 `*-state.js`，只允许导入 contracts，并拒绝非确定性计时/随机行为。
  共享日志读取只处理IO，序号、版本、状态转换和恢复决策仍由原契约/reducer负责。
- 会话、工作流、任务的事实格式与版本不变；恢复不自动重放不确定的外部副作用。
  会话快照发布后会截短冗余日志，修正文档先前“永久保留日志”的过时说明。
- Skill 是按需读取的文档；MCP 保持 JSON-RPC 传输；插件沿用原生 Cordis 或兼容适配器。
  `.skill.pgk`、`.mcp.pgk`、`.plugin.pgk` 保持 formatVersion 1，检查不运行代码，安装默认停用，
  启用/卸载等待对应资源清理，不重启无关手工 MCP 与内置文档工具。
- 复核了初始化、能力与版本协商、ID匹配、分页/循环游标、UTF-8、超时、取消通知、
  HTTP会话失效和关闭。只使用已实现的协议版本；不声明 sampling/elicitation 等未实现能力。
  initialize 不发送取消通知；HTTP 404恢复只重建会话，不自动重发 tools/call。
  参照 [MCP生命周期](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle)、
  [传输](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)、
  [取消](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation)。
- SSE 是实时界面传输，不是永久事件存储或断线精确重放协议。超限关闭等同连接中断，
  EventSource会重连，执行与持久化继续，前端轮询会重新核对运行状态；不能将此理解为
  任意断网期间的每个思考/正文增量都一定重放。终端会重放其有限缓冲。
