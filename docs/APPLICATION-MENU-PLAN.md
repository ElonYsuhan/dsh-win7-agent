# 应用菜单恢复方案

状态：已接入原生菜单、双桌面入口、页面命令和能力同步。沿用当前版本和 Electron 22.3.27 / Node 16.17.1 / Chromium 108，不增加生产依赖。

## 当前实现

- `shell/menu.js` 用空菜单隐藏 macOS 应用菜单，Windows/Linux 移除窗口菜单。
- `shell/main.js` 是打包桌面入口；`src/main/main.js` 是另一桌面入口，两者共用菜单模块，必须同时接入。
- 移除菜单后，macOS 编辑和窗口快捷键由 `before-input-event` 补偿处理。恢复原生 role 后必须移除相应补偿，避免一次按键执行两次。
- 桌面壳、preload、网页桥接已分离；会话和项目操作在 renderer 中，不能由主进程另建一套状态。

## 菜单内容

| 模块 | 首批项目 | 行为与可用条件 |
| --- | --- | --- |
| Agent（macOS） | 关于 Agent、设置、隐藏、隐藏其他、显示全部、退出 | 应用生命周期与原生 role；关于页显示真实版本和运行时 |
| 文件 | 新建会话、添加项目文件夹、关闭当前文件标签、关闭窗口 | 新会话沿用当前项目/普通会话规则；没有文件时禁用关闭标签；不提供手动保存，保留自动保存 |
| 编辑 | 撤销、重做、剪切、复制、粘贴、粘贴并匹配样式、全选 | 使用 Electron role 和当前焦点目标；聊天展示区不产生消息撤销语义；代码编辑器使用其真实撤销栈 |
| 视图 | 显示侧栏、显示文件面板、Markdown 预览、放大、缩小、实际大小、全屏 | 面板项同步勾选；文件面板无可展示资源时禁用；Markdown 项仅在当前 Markdown 文件可预览时可用 |
| 窗口 | 最小化、缩放/还原、切换已有应用窗口 | 操作当前聚焦窗口，区分主窗口与设置窗口；已有窗口列表按平台能力提供 |
| 帮助 | 使用说明、快捷键、打开日志目录、复制诊断信息、关于 Agent | 说明随应用离线打包；诊断排除密钥、消息正文和文件正文；关于在非 macOS 放这里 |

Windows/Linux 的设置、退出放在文件菜单。首批不提供空实现的更新、分享、导出或新建窗口；生产菜单不提供刷新页面和开发者工具，避免丢失正在编辑或生成的状态。

## 展示方式

- macOS 使用系统屏幕顶部菜单栏，保持现有窗口内标题栏及交通灯布局。
- Windows/Linux 在自定义标题栏提供一个菜单入口，展开同一份原生菜单模板；不恢复占高度的传统窗口菜单栏，菜单按钮处于非拖拽区域，避开左右窗口控制区。
- 浏览器访问仅提供可执行的页面命令，不模拟隐藏应用、退出应用等桌面命令。
- 设置窗口只暴露它实际支持的编辑、窗口、帮助和应用操作，不误操作后台主界面的会话。

## 模块边界和调用路径

1. 定义平台无关的界面命令契约：固定 command ID、参数白名单、可用状态与勾选状态。契约不导入 Electron、IO 或 Cordis。
2. `shell/menu.js` 成为 Electron 菜单适配器：根据平台、焦点窗口及能力快照生成模板；本地窗口和编辑操作交给原生 role。
3. 壳通过 preload 的窄接口向目标页面发送白名单命令。renderer 的统一命令处理函数同时服务菜单、页面按钮和快捷键，复用现有新建会话、添加项目、设置与面板逻辑，禁止通过模拟 DOM 点击分发。
4. renderer 回报最小能力快照：页面就绪、是否打开文件、是否 Markdown、面板显示状态等。主进程按发送窗口校验来源并更新对应菜单；页面未就绪、重载或退出时禁用页面命令。执行时再次检查条件，防止过期快照误操作。
5. preload 仅暴露订阅/退订与状态回报，不暴露任意 IPC、任意脚本、文件路径执行或可由页面指定的系统命令。双桌面入口与网页桥接遵守同一命令契约。

菜单属于表现层和宿主适配层，不建立第二个事件总线、服务容器或 Agent 执行器。若未来增加停止执行、会话导出等业务命令，沿现有接口进入 Cordis 管理的服务与插件，由既有状态迁移和 repository 记录事实；菜单不直接修改 reducer、消息数组或会话文件。新增运行时能力须在 profile 注册插件并声明 inject。

## 快捷键与生命周期

- 新建会话建议 Cmd/Ctrl+N，设置 Cmd/Ctrl+,，关闭文件 Cmd/Ctrl+W（无文件时关闭窗口）；最终以同一命令表生成，避免页面、菜单各绑一遍。
- 编辑快捷键优先归当前聚焦编辑器；终端 Ctrl+C 保留中断语义。中文输入法合成期间不触发业务快捷键。
- 菜单不主动抢焦点；切换窗口重算可用状态，窗口销毁解除监听。开发入口和打包入口必须行为一致。
- 不扩展为系统全局快捷键；退出和关闭沿现有自动保存、服务清理流程处理，保存失败时保留窗口并提示，不直接强杀。

## 落地顺序与验收

1. 提取命令契约与复用处理函数，再接入双入口/preload，保持现有页面按钮行为。
2. 恢复 macOS 原生菜单与编辑 role，清除重复快捷键处理；接入 Windows/Linux 标题栏菜单入口。
3. 补齐离线说明、快捷键页、关于与诊断入口，再逐项启用；未完成的项不展示。
4. 经用户要求验证时，检查命令白名单、过期状态、双入口、焦点路由、单次快捷键触发、自动保存失败、窗口销毁和离线场景，运行 `npm run check` 与 `npm run check:node16`，并进行菜单交互验证。
5. Win7 真机验证单独记录，跨平台构建与 Node 16 检查不能替代真机证据。打包、产物保留和发版范围统一遵循根目录 AGENTS.md 及 [桌面交付契约](DESKTOP-DELIVERY.md)，不在本方案另定规则。

未来替换 Electron 时保留命令契约与页面处理函数，仅替换原生菜单、窗口与 IPC 适配器；Cordis 业务层保持独立。

## 当前实现补充

- 文件关闭使用 Cmd/Ctrl+Shift+W，Cmd/Ctrl+W 保持原生关闭窗口，避免覆盖系统快捷键。
- 使用说明、快捷键和关于使用原生离线对话框。未增加新窗口能力。
- macOS 恢复原生编辑 role，移除旧按键补偿；Windows/Linux 菜单按钮由两个 preload 同步创建。
- 页面能力通过限定 IPC 上报，未就绪页面禁用业务菜单；关闭文件、Markdown 预览执行前再次检查当前对象。
- 已进行源码语法检查和打包文件一致性核对；尚未进行多平台原生菜单实机交互验证。
