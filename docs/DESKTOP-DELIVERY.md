# 桌面交付、更新、源码保护与性能契约

2026-10-24：默认交付改为每个平台文件夹中仅一个入口。平台封装已接入，
在线更新与目标机验收仍按本文件分别推进；源码保护已接入默认流水线，范围见下文。上位规则为根目录 AGENTS.md。

## 当前差距

- `scripts/build-desktop.js` 先将 shell、server 和 src 放到内部暂存目录，
  `desktop-distribution.js` 再封装成 Windows EXE、Linux AppImage、Mac 应用包。
  默认封装前执行 agent-source-v1 保护；package.json 的 asar 设置不作为加密证据。
- `shell/main.js` 与 `shell/installer.js` 已有安装登记、构建指纹、本地新包接管、
  PID 身份检查和重启确认。它们不等于可信远程更新源、后台下载、验签及完整回滚。
- 当前自动化有启动与安装器回归、流式内存回归；尚无覆盖五平台的统一启动、
  模块切换性能基线，不能宣布已经满足下述预算。

## 对外只有一个分发文件

| 目标 | 固定分发文件名 | 安装后的运行入口 |
| --- | --- | --- |
| win-x64 | Agent-win-x64/Agent.exe | 当前用户安装目录中的 Agent.exe |
| mac-arm64 | Agent-mac-arm64/Agent.app | Agent.app |
| mac-x64 | Agent-mac-x64/Agent.app | Agent.app |
| linux-x64 | Agent-linux-x64/Agent.AppImage | Agent.AppImage |
| linux-arm64 | Agent-linux-arm64/Agent.AppImage | Agent.AppImage |

这是默认打包输出规范，不能把现有 ZIP 直接改扩展名。Windows EXE 为首次安装并打开的
完整离线入口，不是每次解压的 portable 包；后续从桌面/开始菜单启动已安装程序。
每个平台文件夹内不额外塞 README、依赖或其他入口；校验文件统一在上级目录。用户无需
配置 Node、Python、npm 或另外下载 Electron。Mac 的 .app 本身是一个标准应用包；
不要求把 Chromium、动态库塞成一个裸二进制。
Linux 需验证发行版/glibc、FUSE 或经验证的无 FUSE 启动路径、文件系统执行权限。
Windows 安装与升级必须在 Win7 SP1 x64 验证，不能使用仅新 Windows 支持的安装机制。
打包工具属于构建环境，选型仍须固定版本、离线缓存、记录许可与供应链摘要。

统一流水线为：校验源码 → 构建/裁剪/保护 → 生成不可变载荷与清单 → 平台封装 →
签名 → 隔离安装与升级验证 → 原子发布固定分发名 → 清理旧分发包。
一套清单协调平台封装，不为每个平台另建业务执行容器。开发目录保留可调试源码，
发布目录只接收构建暂存区的输出，绝不直接把整个仓库复制给用户。

在缓存缺失时下载，目标机没有下载流程。系统组件 LGPL 等许可仍按上游要求保留。

`npm run build:desktop` 构建五个平台；指定平台仍通过原入口传参。暂存目录为
`release/.desktop-build/<平台>/`；审计清单为 `release/validation/desktop/<平台>.json`，
记录源码提交、完整载荷文件摘要、封装结果和工具版本。打包从最终工作树读取，核对
封装内的 shell/service/src 每个文件与暂存载荷逐字节一致，并检查 ELF/PE/Mach-O 架构。
Mac 另验证 ad-hoc 签名（不是开发者签名或公证），Windows 暂无发布者签名。

整批请求的所有平台封装验证成功后才替换原有交付目录；每个平台通过同卷改名发布，
改名失败保留旧包，提交失败恢复上一目录。新校验清单写入后，再清理已替换平台的旧
ZIP/散文件；活动目录及无法确认进程占用时保留。Mac 应用包的校验按包内普通文件
逐条列入统一 SHA256SUMS.txt，符号链接目标与权限记录在审计清单中。

AppImage 是只读挂载；NSIS 管理安装位置。两者由随包 `distribution.json` 声明禁止
旧 Shell 目录接管，避免将只读挂载复制到旧散文件位置，或把新安装搬离快捷方式目标。
Mac 与旧目录包继续兼容原逻辑。此适配只属于 Shell 平台层，不改动 Cordis 业务执行。
未来在线更新器替换此平台封装/安装适配，Agent 契约和持久化不变。

平台封装、源码保护、在线更新与性能分别验收；仅完成平台封装不能推断其余能力。

## 安装和更新契约

安装器、更新检查、暂存、平台替换与启动健康检查属于 Shell/平台适配层。
Agent、定时任务和工作流仍由原 Cordis 服务执行和持久化；更新协调器只询问现有
服务的执行/编辑状态，不维护另一套 Agent 进度。无任务状态时也不能忽略未保存表单。

更新状态：idle → checking → downloading → verified → waiting-idle → applying →
health-check → committed；失败进入 failed，切换后失败进入 rolling-back → rolled-back。
这些是安装事实，与会话状态 reducer 分离，必须持久化到独立更新记录以处理断电恢复。

签名清单至少包含协议版本、产品、渠道、发布序号、展示版本、buildId、源码提交、
平台、架构、最低系统/运行时边界、载荷 URL、大小、SHA256、签名与 keyId。
签名覆盖完整清单及载荷摘要；私钥仅在发布环境，客户端内置可信公钥与受控轮换策略。
SHA256 校验不等于发布者认证。URL、跳转和下载源按可信配置限制。
同版本日常包以更高的签名发布序号识别，不用文件修改时间判断新旧。
本地反降级规则不妨碍协调器恢复自己记录且已验证的上一份安装。

1. 主窗口与服务先就绪，后台有界检查，防止重复并发检查；离线/失败沿用当前可用版。
2. 下载到独立暂存目录，有大小、空间和超时限制，可取消；默认全量载荷，增量后续再做。
3. 校验可信签名、平台、架构、序号与哈希；错误包不得进入可执行安装位置。
4. 等待业务安全边界，持久化已有业务事实。活动生成、人工草稿、流程或定时执行存在时
   延后应用；不自动取消用户任务。需要用户保存或授权系统提权时明确提示，不能绕过系统权限。
5. 更新助手核对进程身份，正常退出后在同一卷暂存并执行平台适配的原子切换。
   Windows 处理占用文件，macOS 保留签名、权限和链接，Linux 保留执行权限。
6. 新版启动必须以 buildId、实际服务健康及最小 UI 就绪确认成功。限时失败自动恢复
   上一有效安装，不把“新进程创建成功”当作更新成功。不重放不确定的外部工具操作。
7. 健康确认后提交安装事实，清理无用下载与更老版本；保留一份必要回滚载荷。

用户数据、设置、会话、知识库、能力包均在程序目录之外，不参与文件替换。
若有数据结构升级，必须声明兼容范围并提供迁移/回滚方案；仅恢复旧程序不保证旧数据可读。
离线导入已签名更新包沿同一验证/暂存/切换路径，不建立第二套安装器。

## 源码保护与限制

保护目标是减少自研源码直接泄露并提高逆向成本。能够在客户端解密执行的代码，
其明文或执行语义仍可能被具有调试权限的人恢复，不能保证“绝对不可反编译”。
ASAR、压缩、关闭开发者工具、内置 AES 密钥均不能单独作为保密或权限边界。

- 主进程与服务：先按模块边界打包裁剪，再对自研部分做经验证的压缩/混淆。
  核心模块评估编译或 V8 字节码保护，必须用 Electron22.3.27/Node16.17.1 的实际
  V8 和目标架构生成并验证，不把构建机 Node 生成的缓存当作通用可执行格式。
- 前端：构建分块、压缩和选择性混淆；保留 DOM、IPC、Cordis 服务名、工具名、
  节点协议及用户插件公开 API。浏览器最终需要执行代码，前端不能保存服务端秘密。
- 不发自研源码映射和原始工程；映射与调试符号仅在独立受控构建档案内。
  Skill Markdown、协议 Schema、模板、许可与依法需提供的第三方材料分类管理，
  不将混淆误用于业务数据，也不能破坏离线能力包和旧插件的兼容接口。
- 构建工具固定 Terser 5.31.0、javascript-obfuscator 4.1.1，仅作为devDependencies，
  锁文件固定传递依赖及摘要，不把这些工具带到运行时。运行加载器仅用内置Node16模块，
  不增加生产依赖、Node addon或原生组件。新增工具或运行组件仍需遵守授权与兼容边界。
- 载荷加密如采用，需说明保护对象、密钥边界和离线取舍；运行时持有的密钥可提取，
  不能将加密壳宣传为无法逆向。真正不能暴露的秘密不随客户端发放。

### 2026-10-24：agent-source-v1 实现

默认 `build-desktop` 在内部原始暂存区完成复制后，先执行
`scripts/desktop/source-protection.js`，再生成构建身份、平台封装和签名。原始开发文件
不修改。`--stage-only` 完成相同保护/封装/验证，仅停止在内部暂存区，便于先跑真实包验收
再调用已有原子发布逻辑。不存在跳过保护后自动发布明文的降级路径。
`--legacy-zip` 和性能测试用原始目录仅供内部排查，不作为受保护分发包。

主进程与服务端自研CommonJS模块先压缩/混淆，再分别用AES-256-GCM加密到 `.js.agc`；
原路径 `.js` 只留下调用共享加载器的薄入口。每个构建生成随机256位密钥，每模块独立
随机96位nonce，模块相对路径作为AAD。完整认证成功后才调用原模块 `_compile`，保留
原始filename、dirname、相对require、exports、循环依赖和CommonJS缓存。模块首次使用
时才解密，不全量预读，不把解密源码写到临时磁盘，不注册全局fs钩子；2026-10-28起通过限定应用目录的CommonJS加载校验验证签名摘要，不扫描用户工作区。加载器
是本仓库自研平台适配，不承载Agent业务执行；Cordis装配与四层契约保持不变。

页面脚本和沙箱preload仅压缩/混淆。沙箱preload不能require自定义Node加载器，不降低
sandbox/contextIsolation，不给页面开放Node，不添加unsafe-eval或远程解密服务。浏览器
收到的仍是可执行JS，不能声称这些脚本也已加密或运行时不可查看。vendor、Skill资源、
许可和用户可编辑示例维持资源契约，不改写固定Cordis。工具许可另随包保留。

混淆不重命名公开属性、全局协议或插件服务名称；关闭控制流平坦化、垃圾代码、反调试
循环和selfDefending，不删除诊断日志。构建缓存按源码、工具版本和策略散列索引并校验
内容；仅用于构建提速，不参与目标机运行。

`source-protection.json`记录逐文件策略、原始/变换/入口/密文摘要与工具版本，不含密钥。
任何变换、覆盖率、语法或摘要检查失败都停止打包。发布验收必须再次核对清单、完整
载荷与平台签名。包指纹覆盖`.agc`，但启动仍只读取预生成小清单。GCM能检测损坏，
内置对称密钥不提供发布者认证，不能替代签名清单；离线加载器密钥仍可能被提取。
本轮没有宣称实现V8字节码、原生壳、绝对防逆向或联网更新。

新增回归 `source-protection-smoke` 覆盖篡改不执行、跨路径移用、CommonJS行为、
沙箱preload、浏览器全局、资源保留和禁止明文漏包；纳入check及内嵌Node16全部回归。
`protected-runtime-smoke` 另在真实加密包上运行Cordis、工作流、离线节点扩展、权限与
节点设计回归。`packaged-ui-smoke`验证实际应用启动、主题及浏览器入口隐藏。
`source-protection-perf`以同份源码构建内部明文基线，与加密包交替各30次独立进程启动，
记录首页就绪、模块首次/重复切换、20轮前后资源采样及宿主配置。模块动作统一从rAF
帧边界触发并等待双帧，避免两组触发时点不同导致帧相位噪声。OS缓存未清空，窗口观测是
CDP页面出现而非合成器首帧；测试为空数据Mac开发机，不冒充Win7、真实历史规模或
完整跨平台性能预算验收。报告保存于release/validation/source-protection-perf.json。

## 性能预算与验证

先在固定基准机记录当前未保护包，再比较最终保护包。以下是待验收目标，不是现有实测值：

| 指标 | 首轮目标 P95 |
| --- | --- |
| 已安装程序冷启动至首个可见窗口 | ≤1.5秒 |
| 冷启动至本地首页可交互 | ≤3秒 |
| 已访问模块切换至可操作 | ≤150毫秒 |
| 模块首次打开至本地框架可操作 | ≤500毫秒 |

基准机需记录系统/架构、CPU、内存、存储、数据集和电源模式；Win7 真机单独设定、
记录预算，不能用开发机结果替代。每项至少30次独立测量；首次安装/系统首次验签与
安装后的冷启动分组，模型和网络等待不计入本地 UI 指标但须另外呈现。
对空数据与真实规模历史数据分别测量，避免只优化空白首页。

禁止首屏同步全量扫描历史、加载所有页面、联网检查更新或解密整个载荷。
模块按需加载并有界缓存；离开页面清理监听器、计时器、观察器、请求与图形资源。
模块缓存必须有失效机制，不能用无限常驻页面换取切换速度。
反复往返20轮后，清理并稳定采样的监听器/计时器不随轮数增长；RSS、JS堆、DOM数
需记录趋势与基线差异，新增持续增长即回归。RSS 单点波动不能直接断言内存泄漏。
保护后的启动/切换 P95 相对未保护同提交基线退化不得超过10%，同时满足目标预算。

1. 建立统一构建清单、固定对外文件名与平台封装；验证安装、覆盖安装和离线运行。
2. 打通签名清单、更新协调与事务切换；验证坏签名、错误架构、断网、磁盘不足、
   占用、并发启动、活动任务、断电、健康失败、数据迁移和回滚。
3. 在同一保护流水线中逐步加强混淆/编译；逐平台回归 Cordis、插件、MCP、Skill、
   Agent、工作流、文件读写与取消/恢复，保留可定位构建的诊断信息。
4. 在最终分发程序上完成启动、模块切换及长时间资源验证，再替换旧的已验收分发包。

更新源地址、发布渠道、发布签名密钥及各系统应用签名证书尚未由本次任务配置。
这些是发布自动更新的实际前置条件；未就绪时只交付明确标识的开发验收包，不伪造签名。
平台封装与上述源码保护已接入；旧目录构建只作为内部输入保留。在线更新仍未上线，
不得把封装验证当作 Windows 7 或 Linux 桌面真实安装/图形启动验收。
