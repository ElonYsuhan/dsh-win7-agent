# ADR：知识库 SQLite 文件存储

日期：2026-10-18。用户已授权实施知识库方案。本次增加限定的离线组件例外，
不升级 Electron 22.3.27、Node 16.17.1、Chromium 108，不增加 npm production dependency。

## 决策

使用 SQLite 3.54.0 固定源码与自有独立 bridge，而非 Node native addon 或普通 sql.js。
原文件单独保存，SQLite 直接提交真实文件事务；不通过整库 export 模拟事务。
SQLite 官方版本要求 Windows Vista 或更高；Win7 属于其声明范围，但自编译产物仍需
独立验证 API、CRT 依赖和真实目标机。本次未做 Win7 真机验证，不宣称认证通过。

源码 SHA3-256：8efd453d08a7cfc4c79de5923153036cdc4dcaa254d4f1e617be6a2a98828f9e，
与 https://www.sqlite.org/releaselog/3_54_0.html 对照。源码 ZIP SHA-256、来源与许可证
在 scripts/knowledge-native/UPSTREAM.json；SQLite 源码原样保存，不手工修改。
自有 bridge.c 和可重复构建脚本单独维护。vendor/sqlite/manifest.json 固定每平台产物校验。
构建机工具允许安装，目标机不下载、不安装、不依赖系统 SQLite/Python/Office。

默认 Zig Windows 产物引入 UCRT，不能作为裸 Win7 交付；Windows 构建必须改用 MSVCRT
并检查导入表。不得用「交叉编译成功」替代依赖检查。Mac 两架构分别编译，Linux 静态 musl。
构建入口：node scripts/build-knowledge-native.js [平台文件名]；编译工具与参数见脚本和 manifest。
桌面构建只包含目标平台文件，先校验 hash；ASAR 打包显式 unpack 原生进程目录。

## 事务与资源

同 AGENT_HOME 的知识库由一个服务持有 PID 所有权；SQLite 子进程短时按需执行，
不是常驻数据库服务。repo 串行 SQL，写入使用 BEGIN IMMEDIATE，foreign_keys=ON，
synchronous=FULL、DELETE journal，禁用动态扩展加载。SQL 仅在可信 repository 内生成，
字符串以 UTF-8 hex 字面值编码，不拼接未经编码的用户文本；没有对外 SQL 接口。
bridge 输入/输出分别限 16 MiB，单值 8 MiB，请求 15 秒，DB 最大 32768 页。
工具/界面/HTTP 不能选择数据库路径；知识库原件路径按 SHA-256 构造，上传不接受服务端路径。

原件先写临时文件、fsync 后独占链接发布；文件和数据库没有跨介质事务，失败可能产生孤儿，
但不会发布不存在原件的可用资料。内容块批量提交到未发布 version，最后事务切换 active
version 和 ready 事实。断电后由 SQLite journal 恢复；不能保证磁盘硬件违反 flush 的情形。
数据库新版本/身份不符拒绝打开，不自动降级。当前 schema=3，打开 schema=1/2 时先保留对应 `knowledge.db.schemaN.bak`，再在事务中迁移关联关系；高于已知版本的数据库拒绝打开。

## 第一轮交付范围

可用：知识库新建/重命名/删除、资料导入/更新/逻辑删除、任务取消/中断标记、TXT/MD、
DOCX 正文与表格段落、XLSX 声明范围、中文/英文 FTS5、项目关联、Agent 只读工具与来源预览。
原文件和历史版本保留在本机；删除立即停止检索，但本轮不做物理擦除/空间回收或备份 UI。
重启不自动重放任务；未完成任务标记中断，用户可更新资料重新导入。

本轮一个知识库只关联一个工作目录；关联到另一项目会替换原关联。尚未实现会话级范围选择、
多项目共享关联、目录监听、向量、PDF/OCR。无人值守知识库工具明确拒绝，避免隐式授予任务权限。
这是一轮基础可验收交付，不代表 KNOWLEDGE-BASE-PLAN.md 的全部阶段已完成。

限制：8 MiB/文件、100 万字符、2000 块、500 份资料、32 个库、16 个排队/活动任务。
XLSX 前 10 张表 A1:CV100、公式缓存值；大于范围明确提示，不承诺完整表格索引。
FTS5 输入使用版本 1 的中文单字/双字及英文 token，查询有界，不提供语义理解或企业级规模承诺。

`knowledge.tree` 与 `projectPreview` 是 Knowledge Cordis 服务中的只读管理能力，

### 常用文件预览

项目文件预览复用现有有界 OOXML ZIP/XML 解析器，支持 DOCX 正文、XLSX 前10表
A1:CV100 缓存值、PPTX 前100页文字和 ODT/ODS/ODP 文字；不承诺 Office 原版式。
图片、PDF、音视频返回有界字节并在渲染层以 Blob URL 显示；音视频是否可播放仍取决于
Chromium108编解码器。代码/文本/Markdown 在渲染层处理 UTF-8、UTF-16 和 GB18030，
Markdown 沿用已清理渲染器。HTML 作为源码展示，不执行。未知二进制、旧 DOC/XLS/PPT、
压缩包等保留系统打开入口，不伪装成已解析。媒体上限24MB、文本2MB、Office8MB；
超限提供系统打开。文件范围继续由关联根与 realpath 校验约束，读取有界且关闭句柄。
此为预览能力，不改变索引格式。无新增生产依赖或运行时下载。Node16和构建机验证
格式路由、Office提取、大小限制；真实浏览器验证目录文件预览，未做Win7真机验证。

### 修正共享实例导致的交叉干扰

前一版移动 Code DOM 并共用标签/编辑器，是错误的复用边界，现已撤销。
`file-preview.js` 只接收 kind/text/url 等数据并创建预览节点，不持有标签、编辑器、
选中项、文件接口或页面生命周期。原 Code 与 Knowledge 均调用此渲染函数。
Code 恢复原生文件接口和自动编辑保存；Knowledge 每个库拥有独立的有界标签列表、
活动文件、Blob URL 与专属节点，不向 Code 注入 provider、不移动 Code 节点。
切换库或关闭页面时使在途读取过期；关闭标签释放 Blob URL。周期刷新只更新左侧
事实列表，不重建右侧预览，避免滚动位置及媒体状态丢失。Code 的纯文件布局不再
隐藏打开中的知识库导航。回归验证 Code 原标签/编辑器内容保持、返回后真实写盘、
知识库图片加载及周期刷新节点身份保持。继续保持既有 Win7 运行时版本。

## 会话关联与产物所有权（2026-10-18）

### 语义与边界

新建会话默认普通会话；旁边类型入口与输入区“+”提供普通、项目、知识库三种入口。
知识库会话仍为 recent 普通会话，只增加 knowledgeBaseId/knowledgeBaseName，projectId
必须为空，不移动到项目列表。旧会话不根据当前库、当前项目或历史文件列表自动关联。
服务端以 knowledge_sessions 持久化绑定，绑定后不允许改绑；项目关联参数与库关联冲突
时拒绝。SQLite schema 由2升到3，迁移前保留对应 schema 备份。

### 执行与隔离

Cordis Knowledge 服务提供会话绑定、上下文、目录读取、预览和删除契约。AgentPool
占用运行名额后解析绑定，绑定会话的工作区固定到 knowledge/session-files/<sessionId>。
项目切换不覆盖绑定 Worker 的工作区；普通会话、项目会话和无人值守任务维持旧行为。
知识库工具按该工作区解析绑定，只检索该库；普通项目检索维持既有关联规则。
这复用原 Agent 主循环、工具权限和会话事实仓库，不另建 Agent 执行器。
知识库中的会话文件按绑定表和会话ID组织，不读取当前 Code 会话的浏览历史。
目录与预览再次校验库、会话、真实根路径，不能借用另一个会话的文件路径。
会话目录只记录工作区内实际保存的文件，不承诺自动收集外部路径产物或自动索引。

### 删除

删除前检查该会话没有运行；先持久化 deleted 墓碑，再只移除该 sessionId 的专属
产物目录。失败保留前端会话以便重试，重复删除幂等，墓碑阻止旧客户端重新执行或
重新绑定已删除ID。不遍历项目目录，不按文件名匹配，不删除知识库导入资料，不删
其他会话目录。前端仅移除同ID的 Code 历史索引，并关闭该会话已删除产物的预览标签。
会话聊天本体仍由既有 UI/会话仓库存储；本轮没有改变 Agent 消息 reducer 协议。

### 验证与演进

自动验证双会话同名文件、不同知识库、导入资料保留、越界读取、重复删除、墓碑、
重启关联恢复，以及 AgentPool 的真实运行入口使用专属目录且不被项目切换覆盖。
真实 Chromium108 验证三类型入口、关联创建、recent归类、会话产物树和确认删除。
兼容 Node16.17.1，未新增运行依赖，未做Win7真机验证。未来可替换会话文件仓库与
索引实现，但必须继续以 sessionId 所有权和墓碑为清理边界。

## 多文件与任意格式导入（2026-10-27）

“添加资料”支持文件多选与多文件拖入，不再按扩展名拒收。文件名上限255字符，
容量仍为每文件8 MiB；空文件也可保留。逐个读取和上传，不把整批文件同时读入内存。
上传队列遇到明确的 KNOWLEDGE_QUEUE_FULL 拒绝时有界等待；其他错误逐文件展示并继续，
不重试结果不确定的已提交请求。“停止后续上传”停止尚未提交的文件，已接收的文件
继续按现有知识库任务处理。批次固定目标库，切换页面不把后续文件导入其他库。

保存原件与全文索引分开：TXT/Markdown/JSON/CSV等可解码文本，以及原有 DOCX/XLSX
解析器能提取的内容建立索引；二进制、未知编码、空文件或超出索引容量的文件保存原件，
以零内容块发布版本，明确显示“已保存原件，未建立文本索引”。不声称所有格式均已解析，
不新增 PDF/OCR、向量模型、生产依赖或系统安装器。数据库 schema 仍为3，使用既有
版本与 queued→parsing→indexing→ready 状态迁移，ready 表示版本发布；可检索数量
按实际内容块统计。损坏 Office 解析仍失败，更新失败保留原有效版本。

新增管理接口 `file`：按知识库与资料ID校验归属，校验原件 SHA-256后读取；优先返回
当前已发布版本，首次导入尚未发布时允许管理页面读取该资料的最新原件。删除或跨库请求
被拒绝。此接口不授予 Agent 搜索工具跨项目读取权限，也不改变流程资料仅取已发布版本的
契约。图片/PDF等沿用现有预览组件；不支持预览的文件仍可下载原件。文件不会自动执行。
下载使用原始字节的 Blob，关闭或淘汰预览时回收 URL，保留既有32MiB预览内存预算。

验证扩充 `knowledge-smoke.js` 与 `knowledge-e2e-smoke.js`：任意/无扩展名、空文件、
长文件名、原件字节保真、跨库拒绝；真实 Chromium 文件多选、混合格式、单个超限不阻塞
后续、图片预览、未知格式下载、多文件拖拽和停止未提交文件。平台适配仍为既有 SQLite
独立 bridge 和内嵌 Node16，未将构建机验证当成 Win7 真机验收。
