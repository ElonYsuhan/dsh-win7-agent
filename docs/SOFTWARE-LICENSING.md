# 软件授权机制方案（待实施）

用户于2026-10-24选择：绑定设备，支持人工迁移。本文件定义方案，不代表当前客户端
已经启用授权、签发了许可证或完成联网激活。软件商业授权与节点运行权限是独立概念。

## 首版：离线签名授权

客户端导出 `.agentreq` 申请文件；签发端核查客户与设备后，签发 `.agentlic` 文件。
文件是有界的声明式 JSON，不能执行脚本。签发私钥留在独立签发环境，不进入仓库、
构建缓存、客户端或更新载荷；客户端仅携带公钥与 keyId 白名单。建议使用 Node16
内置 crypto 的 Ed25519 签名，不添加生产依赖。源码加密密钥绝不能代替授权签名密钥。签名能识别伪造授权文件，但本地管理员仍可能
修改客户端验签或授权判断；混淆与加密不构成绝对防破解的DRM。

授权内容包含：schemaVersion、productId、licenseId、customerId、edition、features、
deviceBindingVersion、deviceDigest、issuedAt、notBefore、expiresAt、maintenanceUntil、
sequence 与 keyId。签名覆盖规范化后的完整字段，字段类型/长度、未知字段、重复键和
文件大小都必须检查。sequence 按同一授权递增，防止直接导入过期旧授权；不混用应用
版本号、构建号和授权序号。维护截止日与使用有效期分开，支持永久使用但更新维护到期。

设备标识由平台适配器取得少量稳定设备属性，按产品命名空间和绑定版本计算摘要；
申请文件只包含摘要，不包含原始硬件标识、用户文件或会话。单独保存随机安装ID作为
排查信息，不能把可复制的安装ID当作可靠硬件绑定。设备属性缺失或变化需给出明确
错误与重新申请入口，不能静默放行，也不能因普通软件更新换一个设备身份。
实际采集策略要单独验证 Win7 SP1、两种Mac与两种Linux，避免依赖未经授权的原生组件。

## 人工迁移

客户在新设备导出申请文件，签发端确认迁移并在台账中记录旧/新deviceDigest、客户、
licenseId、授权序号、迁移原因、经办与时间，随后签发新设备授权。不迁移客户端私钥，
不复制旧设备授权作为新授权。用户工作数据的备份/迁移与许可证迁移相互独立。

完全离线的旧设备无法即时获知迁移，因此不能承诺签发新授权后旧设备立刻停用。
首版通过人工确认旧授权作废、签发台账和有界授权有效期管理；后续可增加联网租约
或导入已签名撤销清单。永久离线永久授权尤其不能保证远程撤销或全局单设备同时在线。

## 执行边界

- `contracts/`定义授权声明、请求与结果，不读取设备、文件或系统时间。
- `flow/`根据验签结果、设备摘要、当前时间和已记录事实计算状态，不访问IO。
- 上层原生 Cordis `licensing` 插件负责文件存储、验签、设备适配、事实与审计。
- 通过既有服务入口检查功能 entitlement，前端隐藏按钮仅为提示，不能代替后端检查。
  不建立第二套容器、会话状态或任务循环。
- 状态为未配置、未授权、有效、尚未生效、到期、设备不匹配、需人工核查。公钥未配置
  时不能显示“已授权”。现有安装不能在一次普通更新后被突然锁死，需先明确启用政策。
- 缺授权/到期时仍允许启动、查看、导出、备份已有数据和导入授权；限制新建受控任务。
  正在执行的工作不强行中断，不重放不确定的工具副作用，在既有安全边界处理后续步骤。
- 导入授权使用统一应用弹窗，先预览客户、设备匹配、范围和时间，验证成功后原子保存。
  错误文件不能覆盖唯一有效授权。授权过期不删除、不加密用户工作数据。
- 记录已见时间与授权序号，可识别明显回拨，但完全离线且可恢复磁盘快照的设备无法
  完美防回拨。疑似回拨进入可解释的人工核查状态，不能破坏会话或自动停机。

## 后续联网授权

联网激活沿同一签名协议更新短期租约，并定义离线宽限、撤销、公钥轮换与代理配置。
网络不可达与授权无效分开处理；不得把授权请求放在首屏阻塞路径。长期完全离线客户
继续使用人工签发文件，不要求目标机下载运行时或连接第三方授权服务。

## 验收

篡改、坏签名、未知keyId、错误产品/设备、到期、尚未生效、序号倒退、公钥轮换、
时间回拨、断电导入、旧授权恢复、人工迁移、离线与更新后的设备身份稳定均需回归。
密钥备份/访问控制、客户版本及功能范围由签发政策确定，未设定前不启用强制授权。
