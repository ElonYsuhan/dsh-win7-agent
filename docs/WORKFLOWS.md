# 工作流（首版）

工作流是独立业务模块，入口位于侧栏能力中心下方。列表以卡片管理流程，支持创建、编辑、删除、执行以及查看执行实例。实例可按名称、编号、状态、步骤及时间检索，详情展示步骤状态、输出、错误和产物引用。删除流程保留其历史实例。

## 模块边界

- `src/main/contracts/workflows.js`：版本化流程契约、节点和边校验。
- `src/main/flow/workflow-policy.js`：纯 DAG 校验、拓扑排序、从输出节点反向裁剪依赖。
- `src/main/state/workflow-state.js`：只依赖契约的不可变事件 reducer。
- `src/main/workflows/repository.js`：定义快照、JSONL 执行事实、实例产物、目录所有权锁。
- `src/main/runtime/plugins/workflow-nodes.js`：Cordis 节点能力，注入现有 `llm` 服务。
- `src/main/runtime/plugins/workflows.js`：Cordis 工作流业务服务，注入 `agentConfig`、`workflowNodes`，执行策略并持久化事实；生命周期由 effect 管理。
- `server/workflow-api.js`、Electron IPC、Web bridge：传输适配，均调用同一服务。
- `src/renderer/workflows.js`：独立页面、画布及实例视图状态，不复用 Code 编辑器或知识库页面状态。

Cordis 负责服务装配和生命周期；工作流插件负责业务执行。没有第二个容器或全局事件总线。运行时 profile 统一注册相关插件。工作流不是普通会话，不修改会话状态或项目文件。

## 人工交互、节点执行设计与真实驳回（2026-10-21）

人工节点新增 `interaction` 契约（`src/main/contracts/workflow-interaction.js`，`version:1`，字段 `type` 与 `returnTo`），取代“处理方式多选”作为编辑时的主入口：

| 类型 | 提交语义 | 驳回 |
| --- | --- | --- |
| `handle` 办理 | 完成后一次提交进入下一步，不强制结论 | 不支持（由后续审阅/审批环节决定） |
| `review` 审阅 | 一次动作即视为已审阅并继续，不再勾选确认、不强制填写结论 | 按需点击驳回，填写原因后退回修改 |
| `approve` 审批 | 默认通过，一次提交进入下一步；也可选择驳回 | 必填原因，退回上游人工环节 |

画布的选中节点时属性面板保留三块：节点名称、处理描述（自动节点为执行指令）与执行操作（含「执行设计」按钮）。交互类型与驳回退回目标放在「节点执行设计」预览上方的设置条；附件／填写项／补充意见等“补充内容”、步骤说明与结构化参数收进该弹窗左栏折叠的“更多设置”，打开时临时搬入、关闭后按原位置归还。输入输出端口不再单独配置，见下方端口一节。附件盒子默认关闭，结论默认非必填。旧的 `humanKind` / `humanModes` 组合配置不再在界面暴露（后端仍兼容读取），没有 `interaction` 的定义由 `interactionPreset()` 归纳为办理／审阅／审批之一，行为不变。

编辑页顶部不再有「编辑流程」标题栏，命令条直接贴顶；流程名称与备注显示在右侧流程属性，点击画布空白切换查看。画布左侧工具条沿垂直方向居中，不遮挡节点。卡片本身按“名称在上、文字在下”排版：14px 加粗标题、一条细分隔线、底部一行节点文字摘要（超出按像素省略），类型名只在步骤列表与执行图出现，不再和标题抢视觉。选中卡片后从边缘或边角拖拽调整宽高（宽 200–520、高度至少容纳全部端口），指针显示对应缩放方向，Esc 撤销本次调整，尺寸写进流程定义的节点 `size` 字段并随保存恢复；端口变化时只增高，不会把用户调过的宽度重置。

驳回是真实的流程动作，不是暂停：`submit` 收到 `decision:'reject'` 时校验退回目标（默认最近的上游人工办理节点，可在「节点执行设计」的“驳回退回”里指定，默认按连线自动识别最近的上游人工节点），由 `node-returned` 事实把目标及其下游全部重置为待处理，同时保留 `attempts`、timeline 和已归档的产物文件（产物文件名带 attempt 后缀，历史版本不被覆盖）。退回原因写入执行记录，业务驳回使用警示色表达，不作为技术失败。退回后若会重放已执行过的外部节点（`rest` / `agent` / `tool`），执行器先停在 `external-checkpoint` 暂停点，必须 `resume({confirmExternal:true})` 才会真正重放当前节点；同一退回路径上的下一个外部节点仍需单独确认，避免静默重复外部副作用。退回时保留已填表单值及原附件引用，用户可修改、复用或移除；不能引用其他实例、其他节点的附件。驳回只要求填写原因，不要求先填完本节点的正常办理表单。

画布工具包含选择/移动、连线、框选、分割移动、卡片缩放：空白拖动平移、滚轮围绕指针缩放、框选后拖动任一卡片整体移动。「卡片缩放」图标与「画布缩放」图标独立，启用后显示按下状态与卡片角标，可直接拖动任意卡片边缘或边角调整宽高，无需提前选中；指针显示对应方向，卡片正文点击只选中、不拖动节点或连线。选中后方向键按 2px 微调宽高，Shift 加速为 10px；Esc 取消正在拖动的尺寸并返回选择模式，完成的尺寸随流程保存恢复，画布比例保持不变。原先选择模式下已选卡片的边缘缩放仍兼容。画布缩放图标展开比例滑块、放大、缩小、100%与适应全部；底部保留画布缩放比例，右键也可恢复100%。分割移动只有一个工具：选中后十字两条引导线同时存在，按下开始拖动时按主方向（横向位移大判左右、纵向位移大判上下）只保留一条、另一条立刻消失，两侧按节点中心分别移动距离的一半，正向拉开、反向收拢，所有连线保持原连接关系，Esc 还原本次移动。编辑视口初次打开和整理布局后固定100%，优先保证卡片文字可读；长流程定位起始节点（整理布局时优先当前选中节点），通过空白拖动平移查看后续。能在100%容纳的小图居中显示，只有手动点击“适应全部”才按整图范围缩小。视口调整不改写保存的节点坐标，窗口尺寸变化也不自动重设用户缩放。回归见 `scripts/workflow-interaction-smoke.js`（服务与状态机）与 `scripts/workflow-interaction-e2e-smoke.js`（真实窗口中的交互类型、一键办理、驳回退回与重跑），以及 `scripts/workflow-canvas-e2e-smoke.js`（真实鼠标框选、整组拖动、十字分割自动判向、取消、缩放、连线、卡片缩放及保存重开）。

编辑画布与执行实例流程图均支持普通滚轮围绕鼠标放大/缩小，无需按 Ctrl。执行图的空白区域可拖动平移，也支持聚焦后用 `+` / `-` / `0` 缩放与恢复100%；右侧表单保持普通滚动。当前实例的比例和位置在节点选择、执行状态刷新后保留，缩放不修改流程定义。执行图使用独立 DOM 视口适配，离开页面或重绘前清理 ResizeObserver、拖动捕获与事件监听；不沿用只服务编辑 Canvas 的监听。

多选行为由应用适配器修正，不修改固定版本的 LiteGraph：拖动已选节点不缩小选区，Shift 反选会同时清除库中残留的选中索引，多选组上的连续点击不会触发属性弹出并清空选择。真实鼠标测试覆盖框选、加选/反选和拖动任一卡片让整组等距移动。

属性面板里的折叠区会把关闭状态的子元素设为 `display:none`，此时对内部输入框调用 `focus()` 静默失效。凡是重绘后要聚焦的地方（如“节点处理内容”新增内容块）必须先展开祖先 `<details>` 再聚焦，`renderStructured` 的 `redraw` 已内联这段逻辑。

## 当前能力与边界

内置开始、人工处理、AI 处理、受限 Agent、工具调用、REST 接口、AI 评估、结束八类节点，并保留文本输入、文本整理、保存结果三类旧节点。AI 节点复用现有模型服务和内网鉴权设置，单次请求不开放工具；需要工具时使用受限 Agent 或确定性工具节点。文本整理与 AI 节点支持通过 `{{input}}` 引用上游汇总内容，或通过 `{{input1}}`、`{{input2}}` 分别引用两个输入端口的内容。当前执行器按拓扑顺序逐个执行有效节点，最多同时运行两个实例；未连接到输出节点的节点不会执行。暂未提供节点并发、结果缓存、循环、条件路由或二进制端口。工具能力来自现有统一注册表；暂停、人工等待和显式重试有事实记录并可恢复，重启不会自动重放不确定的外部副作用。

执行前固定流程修订快照。保存使用修订号检查，防止旧窗口覆盖新定义。事实按序持久化并 fsync，重启把未完成实例标为 interrupted，绝不自动重放不确定副作用。显式停止和宿主关闭均发出取消信号，关闭等待节点清理。单次运行时限 10 分钟，单次 AI 请求超时 60 秒；最多 20 个 AI 节点，单节点输出 128KB，累计输出 1MB。定义最多 100 个，实例最多 2000 条，达到上限明确报错。当前取消依赖节点实现遵守 signal。

数据保存在 `AGENT_HOME/workflows/`，与会话、知识库分开。产物由仓储写入当前实例的受控目录，不接受节点提供任意落盘路径。删除定义不删除实例；删除会话也不影响工作流。

## 独立节点扩展

业务 Cordis 插件声明 `inject: ['workflowNodes']`，通过 `ctx.effect(() => ctx.workflowNodes.register(definition, execute))` 注册。definition 包含稳定 type（小写开头的字母、数字、点、下划线或连字符）、name、description。execute 接收 `{node,input,signal,settings}`，返回文本 Promise；必须响应取消，不得记录凭据。register 返回异步撤销函数，移除目录项、取消并等待在途调用。移除扩展后旧定义和执行记录仍可读取，运行时对缺失节点报错。

当前 UI 统一呈现文本参数和文本端口；复杂参数 Schema、图片与视频句柄需要后续版本化扩展。不要绕过服务直接在渲染进程请求模型或执行节点。新增会产生外部副作用的节点必须先明确幂等、权限、取消及恢复语义。

## 人工参与与节点工作台（2026-10-18）

本节替代上文关于“不支持人工等待”和四类内置节点的描述。现增加第五类 `human`，其 `humanKind` 为 `upload` / `review` / `approval`。旧版本图仍使用 version 1，新增字段均有兼容默认值；原有四类节点行为保持不变。节点增加 description、人工处理方式和处理要求。默认新建草稿为上传资料 → AI 分析 → 人工判断 → 保存报告。

执行页为左侧只读流程图、右侧节点工作台。四种主视觉状态为待执行、执行中、已结束、失败；人工等待使用执行中并标注待人工处理。取消和中断保留真实标签，未执行节点保留跳过信息，不伪装为成功。工作台按开始、运行、结束展示时间轴，下方为当前待办。自动节点显示输入、动作摘要、输出、错误及产物；人工节点额外显示附件元信息、意见及审批结果。旧实例没有时间轴时仍能读取已有结果。

新增版本化事件 node-progress / node-waiting / node-submitted。reducer 从 recorded facts 派生 timeline 和待办状态，不维护独立进度标志。node-waiting 持久化 taskId 后实例与节点进入 waiting，退出调度，释放 controller 和自动执行超时计时器。仓储重启保留 waiting；不确定的 pending/running 仍标记 interrupted。人工提交以 runId、nodeId、taskId 匹配当前待办，单条 node-submitted 事实同时保存提交内容并结束该节点；重复或过期提交拒绝。后续执行只读取已完成节点输出，绝不重跑它们。提交后、后续动作前崩溃仍按不确定运行中断处理，不自动重放。

每段自动执行时限10分钟，不包含人工等待时间。等待不占两个自动实例并发名额。停止等待实例会终止待办，不影响其他实例；存在运行或等待实例时拒绝删除流程定义。当前人工操作使用本机应用身份，未实现多人账号、授权分配、电子签名或远程审批。审批不通过作为业务输出传递，首版不会自动回退或跳转。

附件每次提交最多3份、合计512KB，前后端均校验。完整原文件写入 `workflows/uploads/<runId>/<taskId>/<index>`，事实只存受控引用和元信息，不使用上传文件名决定路径。附件引用默认沿上游依赖传递，经过文本中间节点也不会丢失；Agent/工具工作目录复制完整原文件，不再仅取前30份。常见文本扩展额外提取前16000字作为模型可读预览，其他格式由已授权的解析工具读取原件，不声明已完成 Word/PDF 等解析。流程图与属性面板不负责文件 IO。当前单节点、累计输出限制仍适用，超过限制明确报错。

人工结论当前为必填文本，审批还需选择通过或不通过，上传节点必须带附件；任意 Schema 自定义字段、分配审批人、分支与重试将在后续契约版本扩展。执行流程图使用原有图契约的节点与边生成只读布局，编辑仍使用固定版本 LiteGraph；二者不改变执行契约，且不增加运行时依赖。

回归新增：上传→审批→报告、精确实例隔离、防重复提交、waiting 重启恢复、停止待办、时间轴事件顺序，以及 Chromium 108 中真实 File 上传、人工表单提交、执行图和节点工作台。

## 历史参照、多种人工处理与端口

执行页的“查看节点”和“当前待办”分离：选择历史或其他节点后，时间轴展示选中节点，底部仍显示实例当前的人工待办。显式选择不会被轮询强制切回；可使用定位按钮返回当前节点。待办表单按 runId/taskId 保留 DOM，浏览其他节点时不丢失未提交意见或已选择附件；提交或待办失效后清理。该草稿只在当前页面会话内保留，重启后恢复的是已持久化待办和已提交事实，未提交草稿不承诺落盘。

人工节点新增 humanModes 数组，可组合 review（判断）、upload（必须上传）、approval（必须选择审批结果）、read（必须确认已审阅）。旧 humanKind 自动迁移为单元素数组。多选要求全部满足才可提交，后端校验审阅确认并写入事实时间轴。仍不包含多人审批或自动驳回分支。

节点 inputs/outputs 是具名文本端口数组，每侧最多 8 个，名称在同侧唯一。连线记录 slot（目标输入）和 outputSlot（来源输出）。平时只显示已连接端口；鼠标靠近卡片左／右边缘时显示一个临时加号连接点，拖线到目标卡片正文也会自动创建对应端口。支持从输出或输入任一侧开始，正文落点使用空闲端口，保留原有连线；显式落到已有输入端口仍按原规则重连。完成、取消、移出卡片或断开连线后回收临时点和末尾空桩，不保存它们。旧图中间的空槽只隐藏，不重排逻辑编号，保证 {{input2}} 等引用保持原语义。起始／输入节点不接收输入，结束／保存节点不提供输出。执行器按逻辑端口顺序注入 inputs，{{input}} 表示已连接输入的汇总。多个输出仍是同一文本结果的分发端口，附件另外通过标准 files 引用随上游依赖传递。

LiteGraph 的 render_canvas_border 和 show_info 在应用层关闭，不修改固定 vendor 源码。回归覆盖多端口保存与执行、非法端口拒绝、多个源端口接到同一节点不同输入、组合人工要求，以及浏览历史节点时待办草稿保留和轮询不抢回选中项。

## OA 风格节点目录与空白创建

新建流程仅打开空白画布，不生成示例节点；保存前需搭建有效流程。节点菜单提供：开始、人工处理、AI处理、REST接口、评估、文本整理、结束。已有 input/output 节点继续注册并可编辑运行，但不再作为新建菜单入口。

start 不接收上游输入，提供初始文本；end 不提供下游输出，汇总并保存结果。使用新开始/结束节点的图必须有且仅有一个 start、至少一个 end，执行路径必须从 start 连通；依赖裁剪和循环检测保持有效。旧图仍沿原有 source/output 语义执行。

REST 使用独立 Node http/https 适配器执行，平台无关图契约只保存 URL、方法和正文模板。支持 GET/POST/PUT/PATCH/DELETE；POST、PUT、PATCH 发送 JSON，请求体留空时发送 `{input}`。HTTPS 使用系统正常证书校验。首版不提供凭据配置、动态 URL、重定向、自动重试或异步服务任务轮询，不能将请求成功误认为远端长任务已完成。30秒超时、128KB响应上限，并传递取消信号。HTTP非2xx或传输失败产生节点失败事实；不重发结果不确定的写入。

评估节点复用注入的 llm，用户填写评估标准，输出依据、结论、风险、建议。与AI节点共享调用次数及超时限制，结果属于模型分析，不伪装成确定性业务校验。人工结论仍由人工节点提供。

节点标题和端口名称按实际像素宽度省略并裁剪；指令和步骤说明在属性面板保留全文。
绘制由应用适配层完成，不修改 vendor。OA中的条件路由、并行汇合、通知/抄送和子流程尚未实现，菜单不提供空入口；将来需先定义分支、汇合、权限及恢复语义。

## 编辑工作台布局与操作

节点入口与返回/保存位于同一命令栏，使用竖线区分开始、处理、结束和页面操作；小窗口仅节点区域横向滚动，返回和保存保持可见。节点使用独立语义图标，评估明确命名为 AI评估（模型分析），REST是外部接口调用。文本整理保留旧图兼容能力，不再出现在新建菜单。

画布左侧悬浮工具沿画布垂直居中，提供选择/移动、连线、框选、分割移动、卡片缩放五项、画布缩放入口与当前比例。平移通过指针操作适配器仅改变视口，连线模式禁止移动节点并沿用LiteGraph端口连接校验；节点移动标记未保存修改。缩放与视口不改变业务契约，仍使用原固定vendor，无新依赖。

选中不会改变标题颜色或添加发光外框。画布默认节点与运行卡片同为220×92，保留原端口
命中位置；端口增多时自动增高。卡片标题与正文分层（标题 14px 加粗、细线分隔、正文一行），
选中后可从边缘或边角拖拽调整卡片自身大小，尺寸随节点 `size` 保存。样式适配沿用
Canvas2D 和固定 LiteGraph，不改变图 JSON 或运行状态；Chromium108 浏览器回归覆盖

## 会话设计流程与节点辅助分析

`core/workflow-tools` 是 profile 中独立的原生 Cordis 插件，注入 workflows/tools/prompts，以 effect 注册工具并由现有权限闸口执行。新增 workflow_catalog（真实目录与契约）、workflow_read_context（只读事实）、workflow_create_draft（write 权限的新建定义）。AI 只能新建草稿，不覆盖已有定义，不运行流程，也没有人工提交/审批工具；无人值守任务禁止这些工具。草稿经原有契约与拓扑策略校验后持久化，缺省位置自动布局。普通会话即可调用，新建列表的“AI创建流程”提供专用会话入口。

## 连线避障（2026-10-22）

编辑与执行图共用纯 `workflow-link-routing.js`：先尝试短正交通道，受阻时在卡片外扩
边界构成的网格上进行有界 A* 搜索，代价包含长度、转弯、与其他连线的交叉及近距离并行重合。
`routeAll()` 根据稳定编号和距离确定顺序，为已有连线预留通道（默认间隔 10px），再对
拥挤路径做最多两轮、合计 64 次的协商重算，减少后来绕行线与早先连线争抢同一段通道。
线段按水平／竖直坐标建立排序索引，代价查询先二分定位；整批共用 24000 次网格展开预算，
避免把单条线的搜索上限乘以全部连线数。用尽搜索预算时优先保留已找到的避卡路径。
同一端口的分支允许共享短接入段，不相关的连线优先使用独立通道；不承诺任意非平面图零交叉。
端口只保留短接入段，其余路径
绕过全部卡片并留出间距；窄缝逐步降低间距。端口被重叠卡片覆盖或搜索预算耗尽时不绘制
穿卡回退线，编辑器提示移开遮挡卡片。路由不移动节点，不修改流程边或执行顺序。

折线拐角转换为默认半径 12px 的三次贝塞尔曲线，短段按长度收缩半径，并校验控制点凸包
与卡片边界，窄缝继续缩小圆角，避免平滑后重新切进卡片。Canvas 与 SVG 使用同一份
`M/L/C` 几何命令；画布真实调用 `bezierCurveTo`，执行图使用对应的 SVG `C` 路径。

画布按卡片几何、边及端口位置的联合签名缓存整组路径；移动、缩放卡片或修改连接时重算
相关的通道分配，普通选中、主题切换与静止帧复用缓存，框选与连线中点命中沿路由骨架。
缓存只属于当前编辑器，重开时释放，不持久化到业务定义。实现
不修改 LiteGraph vendor，无新增依赖，使用 Node16/Chromium108 支持的语言与 Canvas/SVG。
未来可替换路由算法，流程契约与 Cordis 服务不变。`workflow-routing-smoke.js` 覆盖绕障、
反向、竖向、窄缝、多端口、遮挡拒绝、跨行冲突协商、贝塞尔安全边界及100卡片／294连线规模；真实 Chromium 回归验证
九节点错位跨行布局无共享线段和交叉、真实贝塞尔绘制、静止帧复用、重开路径一致以及拖动后重算、
卡片边缘缩放/取消、缩放入口、深浅主题、保存重开与两个视图的滚轮操作。未做 Win7 真机验证。

右侧执行操作复用实际办理表单构建器，和设计弹窗预览显示同一份处理配置；仅为预览，
不会提交实例、上传文件或作出真实审批。
