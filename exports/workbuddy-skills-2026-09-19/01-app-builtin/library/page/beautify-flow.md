# 一键美化 · 素材/意图 → 精排 HTML page 生成流程

> 本文档承载 `page/entry.md` 中 **「文档 / 素材一键美化 → 生成精排 HTML page」** 这条能力的详细规范。
> 它解决的是 md→html 之外更宽的入口：**用户手里是本地文档 / PPT / PDF / Excel / 图片等素材，或只表达了「做一个可视化 HTML / 汇报页 / 报告页」的意图**，希望产出一页杂志级排版、可分享、可在线编辑的 page。
>
> **与 `md-to-html-flow.md` 的关系**：
> - `md-to-html-flow.md` 承载的是**已存在资料库非 html 节点**（按钮 / 链接给 nodeId）的「一键美化」，以及底层 `md_to_html.py` 生成 + `import_html.py` 挂到源节点下的**执行铁序**。
> - 本文档承载的是**更前置的入口层 + 流程编排层**：把「本地素材 / 泛化可视化意图」这类**新入口**接进来，先抽成 md 母本、再套用美化设计规范（**规范正文见 `beautify/beautify-guide.md`**）产出高质量 html，随后**复用** `md-to-html-flow.md` 的生成与导入流程。
>
> **一句话定位**：本文档 = 「入口放开 + 设计规范 + 播放器分流」；`md-to-html-flow.md` = 「生成器 + 导入挂载」。两者串成完整链路，**不重复**生成细节。

## 0. 触发与入口

> **入口放开说明（对齐 SKILL.md 路由）**：`md-to-html-flow.md` 的入口收紧为「必须指向已存在资料库节点」，是为了防止与主 agent 抢生成。**本文档是那条限制的合法补充入口**——覆盖「没有现成资料库节点、但用户明确要一页可视化 HTML」的场景。二者不冲突：有 nodeId 走 md-to-html-flow 入口 A/B；无 nodeId、给素材或表达可视化意图走本文档。

命中**以下任一入口**即进入本流程：

### 入口甲 · 「制作可视化 HTML」意图（非建站/应用）

用户在对话里表达要做**一页可视化 HTML**，且**不是**要做多页网站 / Web 应用 / 前端工程，例如：

- 「做个可视化 HTML / 做一页 HTML / 生成一个网页展示」
- 「做个报告页 / 分析页 / 汇报页 / 展示页 / 数据页」
- 「把这段内容做成好看的页面 / 美化成网页」

> **与「建站 / Web 应用」区分**：用户说「做一个网站 / 多页站点 / 带路由的应用 / 前端项目 / 后台系统」等**工程化多页应用**诉求时，**不进本流程**（那是主 agent 的前端工程任务，不是资料库单页 page）。本流程只产出**单文件 HTML page**。

### 入口乙 · 本地素材 → 生成 HTML（单素材或综合素材）

用户给出**本地素材**并要求「生成 HTML / 做成页面 / 美化 / 做成汇报分享」，素材类型包括（单个或多个综合）：

- 文档：`.md` / `.doc` / `.docx` / `.txt`
- 演示：`.ppt` / `.pptx`
- PDF：`.pdf`
- 表格：`.xls` / `.xlsx` / `.csv`
- 图片：`.png` / `.jpg` / `.jpeg` / `.webp` 等
- 上述若干种的**综合素材包**（如「这几个文件 + 几张图，帮我做成一页汇报」）

### 入口丙 · 明确的汇报 / 分享场景

用户表达要「做一份汇报 / 周报月报季报 / 复盘 / 述职 / 路演 / pitch / 演示」并希望产出可分享页面时，进入本流程（后续在 §1 判定长页 or PPT 演示）。

### 不进本流程的情况

- 用户给的是**已存在资料库节点**（nodeId / `workbuddy.cn/space` 链接）+ 可视化意图 → 走 `md-to-html-flow.md` 入口 A/B。
- 用户要**建站 / 多页应用 / 前端工程** → 交主 agent，不走资料库单页 page。
- 用户要**编辑已托管 page**（给 page 详情页 / 发布态链接要改）→ 走 `edit-flow.md`（见 `entry.md` §7 与 P0 kind 仲裁）。

## 1. 意图分流：静态可视化长页 vs 动态数据页 vs PPT 演示

进入本流程后，**第一步判定产物形态**，决定后续链路。判定由 AI 读素材/意图完成，**不向用户暴露技术判断逻辑**（不要问「要静态还是动态」「要不要建表」这类用户答不上的技术问题）。

```
                       ┌─ 有明确「数据管理 / 表单 / 可增删改的数据」意图（strong/medium 且用户确认要管理）
                       │      → 【动态数据页】：走 data-page-flow.md 改造分支（接 database，字段可增删改）
用户素材 / 意图 ────────┤
                       ├─ 有明确「PPT / 演示 / 翻页 / 幻灯片」意图，或内容呈短密度分段叙事
                       │      → 【PPT 演示】：--format presentation（见 md-to-html-flow §4.1）
                       │
                       └─ 其余「可视化 / 汇报 / 报告 / 分析展示」诉求（无数据管理需求）
                              → 【静态可视化长页】：--format page + §3 美化规范（引用 `beautify/beautify-guide.md`）
```

### 1.1 三态判据

| 产物形态 | 判据（命中即归此类） | 生成链路 |
| --- | --- | --- |
| **动态数据页** | 素材含表单 / 表格且用户要「随时改数据 / 多人维护 / 存数据」；或用户描述了要管理的字段（≥2 个数据名词）；或明确「做个能录入 / 能改的数据页 / 看板」 | `data-page-flow.md` 改造分支（parse_html→建 database→改造→上传），database 字段**可持续增删改**并同步 html（见 `entry.md` §动态字段联动） |
| **PPT 演示** | 用户明说「PPT / 演示 / 幻灯片 / 翻页 / presentation / 路演」等汇报诉求；或内容是「H1 + 3~8 个短 section、每节 ≤150 字」的短密度叙事 | `md_to_html.py --format presentation` 出翻页空框架，再按 `wbp-presentation-contract.md` §7.10 / §12 逐张建版，播放器走**专业演示态**（见 §5） |
| **静态可视化长页**（默认） | 上述都不满足的一般「可视化 / 汇报 / 报告 / 分析 / 展示」页；信息密度高、以阅读为主、无数据管理诉求 | `md_to_html.py --format page`（滚动长页）+ §3 美化规范（`beautify/beautify-guide.md`），播放器走**全屏滚动态**（见 §5） |

> **默认落原生资料库在线 page**：无论哪一态，终态都是**导入资料库成为在线 page 节点**（复用 §6 铁序），不是停在本地 html。统一口径见 `entry.md`「生成类请求总入口」。

### 1.2 数据管理意图的询问克制（沿用 data-page-flow.md §0）

- 数据管理意图**明确**（strong）→ 直接走动态数据页，动手时一句话告知即可，**不询问**。
- 真分不清（medium，只看到重复卡片/列表）→ 只问**业务问题**（「这些数据以后要不要随时改 / 多人维护？」），**绝不**问技术路径。
- 无数据管理信号（weak/none）→ 静默走**静态可视化长页**，不打扰用户。

## 2. 素材 → md 母本（依赖宿主读取能力）

> **本 skill 不自写素材解析脚本**：doc/ppt/pdf/excel/图片的读取与内容抽取，**由宿主 agent 的多模态 / 文件读取能力完成**（宿主 Read 能力可直接读 pdf / 图片；Office 文档由 agent 抽取文本与结构）。本 skill 只约定「先抽成 md 母本，再进生成链路」这一流程契约。

### 2.1 抽取原则

| 素材类型 | 抽取方式（交由宿主 agent） | 落地为 md 时 |
| --- | --- | --- |
| md / txt / doc / docx | 读取正文，保留标题层级 / 列表 / 表格 | 直接作 md 母本 |
| ppt / pptx | 逐页抽标题 + 要点 + 备注；页序即叙事序 | 每页 → 一个 H2 section |
| pdf | 抽正文 + 标题结构（宿主 Read 支持 pdf 逐页） | 按章节/标题切 H1/H2 |
| xls / xlsx / csv | 抽表结构 + 关键数据；判断是否是「要管理的数据」（若是 → 转 §1 动态数据页） | 表格 → md 表格 / 数据亮点 |
| 图片 | 宿主多模态识图，抽取图中信息 + 作为 `ImageFrame` 素材；图片本身作 page 图片资源 | 图注 + 引用图片 |
| 综合素材包 | 逐个抽取后**融合重排**成一条叙事主线（见 §3.1 综合素材融合 / `beautify/beautify-guide.md` 内容处理原则） | 合成单一 md 母本 |

### 2.2 抽取后必做的净化门（继承 md-to-html-flow §①.5）

md 母本**不得**混入任何过程信息（token / 凭证 / 工具 raw 调用 / agent 中间思考 / 本地绝对路径）。发现即先剥离再生成——`md_to_html.py` 内置凭证扫描兜底，母本含特征会直接中止生成。

### 2.3 图片素材的特殊处理（关联 §8 图片展示链路）

若素材含图片且 page 需要**展示图片**：图片不写死进 html，而是走 **database image 字段** 映射（详见 `entry.md` §图片展示 page 链路 与 `data-page-flow.md`）。这样后续可通过对话持续换图。

## 3. 文档美化设计规范（引用 beautify/beautify-guide.md）

> **单一事实源**：美化设计规范的**唯一权威**是 `beautify/beautify-guide.md` + 同目录 `beautify/visual-techniques.md`（技法代码库）。本节不详述，**避免副本分叉**。

进入本流程生成 html 时，`read_file` 读取 `beautify/beautify-guide.md`（按需读 `beautify/visual-techniques.md`），据此对内容做叙事重构、按受众调密度、富化视觉。`md_to_html.py` 只出结构、不做设计（`:root` 变量填为**无彩占位灰**），不改信息层级；agent 按规范加工 md 内容**再**喂生成器，或基于生成器产物做富化——实际配色/字体由美化阶段**覆写 `:root` 变量**落地，占位灰残留即视为未美化。

### 3.1 本流程的补充约定（beautify-guide.md 之外）

- **风格路由落地方式**：`beautify-guide.md` 风格路由表确定气质标签与配色后，通过**覆写 `md_to_html.py` 产物的 `:root` 变量**（`--accent`/`--bg`/`--panel`/`--text` 等）落地。翻页演示（`--format presentation`）另须按 `wbp-presentation-contract.md` §7.10 / §12 逐张建版。
- **综合素材融合**：多素材（综合素材包）要**融合成一条叙事主线**，不是把几个文件简单拼接——按 `beautify-guide.md` 的叙事骨架重排后再生成。

## 4. 多端自适应硬约束（PC + 移动端）

> **必达硬约束**：本流程生成的所有 page（静态长页 / 动态数据页 / PPT 演示）**必须在 PC 与移动端都能正常浏览、样式不错乱**。这是生成的验收项，不是可选项。

| 约束 | 要求 |
| --- | --- |
| **viewport** | `<head>` 必含 `<meta name="viewport" content="width=device-width, initial-scale=1">`（`md_to_html.py` 模板已内置，富化/手改时不得删除） |
| **流式布局** | 宽度用 `%` / `min()` / `clamp()` / `fr`，不写死 px 宽；容器 `max-width` + 居中，两侧留安全边距 |
| **响应式断点** | 至少覆盖移动端（<640px）单列堆叠、平板（640~1024px）、桌面（>1024px）多列；多列网格在窄屏自动降为单列 |
| **字号自适应** | Hero / Heading 用 `clamp()` 随视口缩放（如 `clamp(28px, 5vw, 56px)`），移动端不溢出 |
| **图片 / 表格** | 图片 `max-width:100%; height:auto`；宽表格在窄屏 `overflow-x:auto` 横向滚动，不撑破布局 |
| **触控友好** | 可点元素移动端触控目标 ≥44×44px；hover 态在触屏有非 hover 的替代反馈 |
| **PPT 演示的移动端** | presentation 16:9 设计盒在移动端**等比缩放**适配（`data-design-w/h` + 播放器缩放），不横向溢出 |
| **安全区** | 适配刘海屏 `env(safe-area-inset-*)`（页脚 / 固定条） |

自检：生成后必须确认「移动端窄屏无横向滚动溢出、多列已降级为单列、Hero 字号不溢出」（见 §7 清单）。

## 5. 播放器意图分流（演示态 vs 全屏滚动态）

> **核心诉求**：page 导入资料库后，用户点「播放」按钮时，播放器应**根据 html 类型自动分流**到两种截然不同的体验。分流依据是 html 的**根标记**，`md_to_html.py` 生成时即写入，播放器只看根标记即可判定。

### 5.1 两种播放态

| html 类型 | 生成参数 | 根标记（`<html>` 上） | 点「播放」后的体验 |
| --- | --- | --- | --- |
| **PPT 分页汇报** | `--format presentation` | `<html ... data-wbp data-wbp-version="1.1" data-aspect="16:9" ...>` | **专业演示播放器**：逐页翻页、`.is-active` 入场动画、提词器 / 逐字稿（`data-wbp-notes`）、过场——即现有带提词器的演示播放器 |
| **一般可视化长页** | `--format page`（默认） | `<html ... data-sp-mode="scroll">` | **全屏滚动浏览**：直接进全屏、纯上下滚动阅读，**无分页、无提词器、无翻页控件**——单纯沉浸式全屏 |

### 5.2 分流标记契约（生成侧硬约定）

`md_to_html.py` 生成时写入的根标记是播放器分流的唯一依据：

- **presentation 档**：`<html>` 带 `data-wbp`（及 `data-wbp-version` / `data-aspect` / `data-design-w` / `data-design-h`）。播放器**检测到 `data-wbp` → 走专业演示态**（翻页 + 提词器）。此标记 `md_to_html.py --format presentation` 已内置，不需新增。
- **page 长页档**：`<html>` 带 `data-sp-mode="scroll"`。播放器**检测到无 `data-wbp` 且 `data-sp-mode="scroll"` → 走全屏滚动态**（沉浸全屏、纯滚动、无控件）。

> **播放器判定优先级**：① 有 `data-wbp` → 演示态；② 否则有 `data-sp-mode="scroll"` → 全屏滚动态；③ 都没有（历史/外部 html）→ 播放器按保守默认（全屏滚动态）处理，保证不误进翻页态。

分流标记只影响播放器的**播放体验路由**，不影响 html 本身的浏览态渲染（长页在 iframe 里本就是滚动长页，演示档在浏览态竖直堆叠——见 `md-to-html-flow.md` §4.1）。

## 6. 生成后入库（复用 md-to-html-flow 导入挂载）

美化生成出本地 html 后，按产物形态入库（生成细节复用 `md-to-html-flow.md`，不在此重复）：

> ⚠️ **导入前先过美化硬门**：静态长页 / 演示导入前须已完成 §3 美化富化并拿到 `md-to-html-flow.md` §4.2 的 `BEAUTIFY_OK` 信号，不得直接导入 `md_to_html.py` 基线产物。

| 产物形态 | 入库链路 |
| --- | --- |
| **静态可视化长页** | `import_html.py` 导入即完成，产出自包含静态 html。**不建 database、不注入 SDK、不回绑**。 |
| **PPT 演示** | `md_to_html.py --format presentation` 产出 WBP native 档，`import_html.py` 导入。 |
| **动态数据页** | 走 `data-page-flow.md` 改造分支：parse_html→建 database（业务字段，可增删改）→改造 HTML 注入读写 SDK→上传，字段变更同步 html（见 `entry.md` §动态字段联动）。 |

> **终态必达**：导入资料库、拿到访问 url 是必达终态。停在「本地生成 html」= 任务未完成。生成细节与自检以 `md-to-html-flow.md` 为准。

## 8. 安全边界（继承 SKILL.md §安全底线 / entry.md §12）

- 素材读取仅处理用户**显式给出**的本地路径，不遍历目录、不通配。
- md 母本与产物 html **不含** token / Cookie / 凭证 / 本地绝对路径 / 工具 raw / agent 中间思考。
- 生成 html 对文本做 HTML 转义，避免注入；不用 `innerHTML` 拼接存量内容。
- 外链 CDN / 字体固定版本号，禁止 `@latest`；只用白名单域（`cdn.jsdelivr.net` / `cdnjs.cloudflare.com` / `unpkg.com` / `esm.sh`），详见 `beautify/beautify-guide.md`。
- 本流程只产出**单文件 HTML page**，不产出多页站点 / 后端代码。
